# Pitch rehearsal

Read the actual challenge, PLAN.md, DEMO_SCRIPT.md and deck if available. Use
README.md only for background; distinguish documented judging criteria from
your own assessment. No code changes are needed for a rehearsal unless asked.

- Time the proposed narration and clicks against 180 seconds. Reserve space
  for actual UI waits and one recovery line. Cut a feature before speeding up
  an explanation that judges need to follow.
- Check one persona, one painful moment, a visible before/after, one quantified
  benefit with assumptions, human approval and a concrete pilot next step.
- Identify which demo actions are live, replayed or mocked. Make that distinction
  honest in narration; never present a mock as a working integration.
- Score business value, sponsor fit, visible demo, feasibility/trust and clarity
  with evidence. Scores are rehearsal judgments, not predicted competition rank.
- Ask the five hardest questions this particular implementation invites: model
  error, privacy, approval, impact arithmetic, differentiation or operating cost.
  Give answers grounded in what exists; mark missing evidence instead of bluffing.

Deliver the three highest-value edits feasible in the time left, a timed script,
the questions and answers, and a backup-demo transition. Use impact-calc for
arithmetic and be-domain for claims needing verification. Do not add features
or rebuild the deck merely because the user requested critique.
